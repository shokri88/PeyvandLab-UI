# PeyvandLab UI — قالب موبایل و PWA پیوند

۴۲ صفحه HTML مستقل، فارسی و RTL با Bootstrap 5.3.3؛ بدون نیاز به build یا فریم‌ورک. همه محتوا و لینک‌ها داخل HTML هستند. JS فقط تعامل‌ها را فعال می‌کند. بخش کاربری در این نسخه به‌صورت HTML و جریان نمایشی ورود طراحی شده است.

## اجرا

از ریشه پروژه `python3 -m http.server 8080` را اجرا و `http://localhost:8080` را باز کنید. باز کردن مستقیم فایل HTML برای بررسی ظاهر ممکن است؛ نصب PWA و سرویس‌ورکر به HTTPS یا localhost نیاز دارد. برای انتشار، تمام پوشه را روی یک میزبان استاتیک با MIME صحیح manifest و JavaScript قرار دهید.

- `preparation.html`, `faq.html`: آمادگی و سوالات متداول
- `departments.html`, `department.html`: ده بخش تخصصی و معرفی بخش‌ها
- `home-sampling.html`, `child-sampling.html`: خدمات نمونه‌گیری
- `doctors.html`, `about.html`, `contact.html`: پزشکان، درباره و تماس

- `result-guide.html`, `physician-services.html`, `collaborator-services.html`: راهنمای داخلی خدمات؛ اتصال واقعی این سرویس‌ها در این مرحله انجام نشده است
- `partners.html`, `international.html`, `careers.html`: همکاران، بیماران بین‌الملل و همکاری
- `privacy.html`, `offline.html`: شفافیت داده‌ها و وضعیت آفلاین

## ساختار

```
assets/
  css/       app.css (رنگ‌ها و اجزا)، fonts.css (فونت مستقل)
  js/        app.js (تعامل‌های مشترک)
  images/    تصاویر واقعی سایت، لوگو و icons/
  vendor/    bootstrap/ (CSS، JS و مجوز)
  plugin/    محل افزونه‌های اختیاری آینده
  font/      Pelak سایت اصلی، Vazirmatn جایگزین و مجوز OFL
scripts/     اعتبارسنجی و تنظیم SEO انتشار
manifest.webmanifest
sw.js
```

رنگ‌ها در متغیرهای ابتدای app.css تعریف شده‌اند. سیستم اندازه‌گذاری Bootstrap (`container`, `row`, `col-*`, `g-*`) برای صفحه‌ها حفظ شده است؛ کارت‌ها با CSS Grid و Flex مکمل پیاده‌سازی شده‌اند. فونت پلاک از دارایی‌های سایت اصلی گرفته شده؛ مجوز استفاده در دامنه/اپ مقصد باید توسط مالک پروژه معتبر باشد. Vazirmatn با مجوز OFL نیز به‌عنوان جایگزین محلی موجود است.

## محدوده عملکرد

- هیچ بک‌اند، احراز هویت واقعی، پرداخت، آپلود نسخه یا ثبت نوبت واقعی پیاده‌سازی نشده است. ورود و کاربری فقط پیش‌نمایش رابط هستند.
- فرم پذیرش شش‌مرحله‌ای نمایشی است؛ فیلدها و فایل‌های آزمایشی را فقط در همان صفحه نگه می‌دارد و به سرور یا حافظه پایدار مرورگر ارسال/ذخیره نمی‌کند.
- تمام لینک‌های محتوایی و خدماتی داخل قالب هستند. هیچ لینک وبی به دامنه‌های سایت قبلی، تور یا سامانه‌های جواب‌دهی وجود ندارد. تماس تلفنی، ایمیل و مسیریابی حفظ شده‌اند.
- جست‌وجو، فیلتر، اعتبارسنجی نمایشی، منوی offcanvas، accordion و کاروسل فعال‌اند.
- کاروسل عمداً خودکار حرکت نمی‌کند؛ قابل لمس، کنترل با دکمه و صفحه‌کلید است. ترجیح کاهش حرکت رعایت می‌شود.
- نصب مرورگری، Splash مستقل، آیکن‌های any/maskable و fallback آفلاین موجودند. iOS از راهنمای Add to Home Screen استفاده می‌کند.
- کش فقط شامل پوسته و صفحات عمومی بدون query است؛ صفحات پذیرش، جواب، راهنمای دسترسی اختصاصی و اطلاعات شخصی کش نمی‌شوند. صفحات عمومی پس از مشاهده آنلاین آفلاین می‌شوند؛ تمام صفحات از قبل دانلود نمی‌شوند.
- پیش از تغییر نسخه، مقدار CACHE در sw.js را افزایش دهید. نسخه جدید پس از بسته شدن کلاینت‌های قبلی فعال می‌شود.
- اطلاعات عمومی و تصاویر از سایت پیوند گرفته شده‌اند. محتوا در این نسخه خلاصه است؛ اطلاعات تخصصی تست‌ها، رزومه پزشکان، بیمه‌ها و متن حقوقی باید پیش از انتشار نهایی تأیید و تکمیل شود. ادعای بررسی پزشکی نهایی وجود ندارد.

## SEO

این مخزن به‌صورت پیش‌نمایش `noindex,follow` دارد تا نسخه ناتمام با سایت اصلی رقابت نکند. هر صفحه title، description، زبان فارسی، RTL و یک H1 دارد؛ محتوا برای موتور جست‌وجو در HTML حاضر است. Canonical فرضی و تاریخ/نظر/اسکیمای جعلی اضافه نشده است.

پس از تعیین دامنه واقعی و تأیید محتوا:

```
python3 scripts/configure-seo.py https://YOUR-ACTUAL-APP-DOMAIN/
python3 scripts/validate.py
```

اسکریپت canonical، OG URL و تصویر، sitemap و robots را برای دامنه واقعی می‌سازد و فقط صفحات عمومی را از noindex خارج می‌کند. اگر محتوای اپ با سایت اصلی یکسان است، پیش از این مرحله canonical به نسخه اصلی یا سیاست noindex را تصمیم‌گیری کنید؛ اسکریپت پیش‌فرض self-canonical برای اپ مستقل است. تصاویر شبکه اجتماعی اختصاصی و داده ساختاریافته فقط بعد از تأیید آدرس نهایی و اطلاعات واقعی اضافه شوند.

## بررسی

```
python3 scripts/validate.py
node --check assets/js/app.js
node --check sw.js
```

چک‌های استاتیک لینک/دارایی محلی، ID، H1، توضیحات، RTL و manifest را بررسی می‌کنند. تست نهایی نصب و standalone روی Android و iOS، تکمیل اطلاعات تخصصی و اتصال API جزو مرحله یکپارچه‌سازی است.

گزارش بررسی این نسخه در `VALIDATION-fa.md` است. تست سیاست کش نیز با `node scripts/check-sw.cjs` اجرا می‌شود.

## تغییر صفحه اصلی — ۱۴۰۵/۰۸/۱۰

- خدمات سریع: Bootstrap Carousel با دو گروه چهارتایی؛ همان کارت‌های قبلی در گروه اول، چهار خدمت دیگر در گروه دوم. موبایل ۲×۲ و دسکتاپ چهار ستون.
- بخش‌ها: کاروسل تصویری تک‌ردیف شامل هر ده بخش؛ لینک‌ها به بخش متناظر `department.html` می‌روند.
- پزشکان، ایزوها و اخبار: کاروسل تک‌ردیف با تصاویر محلی سایت اصلی. لینک خبرها به جزئیات مستقل داخل همین قالب می‌رود.
- CSS و JS اختصاصی این تغییر فقط در index.html بارگذاری می‌شوند: `assets/css/home-carousels.css` و `assets/js/home-carousels.js`.
- کاروسل‌های تک‌ردیف از scroll-snap مرورگر استفاده می‌کنند: لمس، دکمه قبلی/بعدی، کلیدهای جهت و Home/End؛ بدون تولید محتوا در JS و بدون حرکت خودکار. وقتی همه کارت‌ها در عرض جا شوند، دکمه‌ها مخفی می‌شوند.
- نسخه کش PWA به v2 ارتقا یافت و فایل‌های CSS/JS جدید وارد پوسته آفلاین شدند.

### فهرست مجله و اخبار

`blog.html` و `news.html` از ردیف Bootstrap با ستون‌های `col-12` و کارت‌های `w-100` استفاده می‌کنند؛ هر کارت در یک ردیف تمام‌عرض است. خبرهای صفحه اخبار همان شش خبر صفحه اصلی با تصاویر محلی و لینک به صفحه جزئیات داخلی هستند. استایل عمومی کارت‌ها و کاروسل‌های خانه تغییر نکرده است. نسخه کش این تغییر v3 است.

## استقلال از سایت قبلی

هیچ مقصد وبی در HTML نباید به دامنه‌های peyvandlab.me، peyvandlab.com یا labpeyvand.ir و زیردامنه‌های آن‌ها اشاره کند. این قاعده در scripts/validate.py بررسی می‌شود. آدرس ایمیل تماس، لینک تلفن و مسیریابی لینک وب به سایت قبلی محسوب نمی‌شوند.

- جزئیات شش خبر در شش HTML مستقل قرار دارد؛ تصاویر قبلی دوباره استفاده شده‌اند.
- مقالات موجود در صفحه خودشان باز می‌شوند و دکمه بازگشت به مجله دارند.
- تور بیرونی با گالری محلی جایگزین شده است؛ این گالری تصاویر دوبعدی دارد و نمایشگر ۳۶۰ درجه نیست.
- پذیرش نمایشی در همان صفحه و راهنمای جواب‌دهی و خدمات همکاران در صفحات داخلی است. هیچ نتیجه واقعی، احراز هویت سمت سرور، پرداخت یا ثبت نوبتی اضافه نشده است. ورود کاربری و تاریخچه با داده‌های نمونه طراحی شده‌اند.
- نسخه کش v4 است؛ شش خبر و گالری به صفحات عمومی قابل کش اضافه شده‌اند.

## بخش کاربری و OTP — پیش‌نمایش HTML

- `login.html`: ورود شماره همراه و اعتبارسنجی؛ پذیرش اعداد فارسی/عربی/انگلیسی و قالب +98.
- `verify.html`: کد نمایشی 123456، اعتبار دو دقیقه، دریافت مجدد پس از ۶۰ ثانیه و حداکثر پنج تلاش در هر مرحله نمایشی. پیامک ارسال نمی‌شود.
- `history.html`: شش کارت درخواست نمونه با وضعیت، کد رهگیری، شماره پذیرش، تاریخ و زمان شمسی؛ جست‌وجو و فیلتر وضعیت.
- `request-details.html?request=1001`: اطلاعات پذیرش، هویت، خدمت، مدارک، فاکتور، پرداخت‌ها و رویدادها. شناسه‌های 1001 تا 1006 داده HTML مستقل داخل همان فایل دارند؛ شناسه نامعتبر حالت «پیدا نشد» دارد. اسناد و نتیجه آزمایش واقعی وجود ندارند.
- `profile.html`: ویرایش مشخصات نمایشی و ذخیره محلی در نشست مرورگر.
- `logout.html`: تأیید خروج و حذف کلیدهای متعلق به همین پیش‌نمایش.
- منوی پایین همه صفحات عادی: کاربری با تاریخچه، ویرایش و خروج. لینک ورود در ابتدای زیرمنو وجود دارد و منوی بالای سایت حفظ شده است.
- `assets/css/account.css`: استایل صفحات کاربری؛ استایل منوی مشترک در app.css است.
- `assets/js/account.js`: جریان نمایشی OTP، فیلتر تاریخچه، انتخاب درخواست، ذخیره نمونه پروفایل و وضعیت منو. محتوا و لینک‌ها در HTML هستند.

### مرز فنی و امنیتی

این جریان **احراز هویت واقعی نیست**؛ کد 123456 و محدودیت‌های مرورگر صرفاً برای نمایش UX هستند و کنترل دسترسی امن ایجاد نمی‌کنند. نشست نمایشی ۳۰ دقیقه‌ای با sessionStorage و سه کلید `peyvand.demoSession`، `peyvand.demoOtp` و `peyvand.demoProfile` پیاده شده است. شماره همراه کامل ذخیره نمی‌شود و هیچ درخواستی به سرویس پیامک یا سرور ارسال نمی‌شود. اطلاعات واقعی بیمار را در این قالب قرار ندهید. صفحات حساب در کش PWA و sitemap تولیدی وارد نمی‌شوند و noindex می‌مانند.

برای عملیاتی‌سازی، تولید/ارسال/اعتبارسنجی و مصرف یک‌باره OTP، انقضا، محدودیت ارسال و تلاش، نشست امن، احراز مالکیت درخواست‌ها، دریافت مدارک و پرداخت باید سمت سرور پیاده‌سازی شوند. تاریخچه این مخزن صرفاً داده نمونه است. نسخه کش این تغییر v5 است.

قاعده `.prose a:not(.btn)` فقط لینک متنی را رنگ و زیرخط می‌دهد؛ رنگ و حالت‌های دکمه از Bootstrap می‌آیند.

### کارت‌های مالی جزئیات درخواست

در `request-details.html` هر ردیف فاکتور و پرداخت به کارت مستقل با عنوان و زوج‌های معنایی `dt/dd` تبدیل شده است. جمع فاکتور و حالت بدون پرداخت، بلوک‌های جدا دارند. جدول، `table-responsive` و حداقل عرض ۵۴۰ پیکسل از این صفحه حذف شده‌اند؛ در عرض کوچک فیلدها زیر هم قرار می‌گیرند و متن طولانی می‌شکند. اطلاعات مالی مخفی یا بریده نمی‌شود. کش این تغییر v6 است.


## پذیرش آنلاین مرحله‌ای

`admission.html` مسیر شش‌مرحله‌ای ورود، انتخاب کارت خدمت (آزمایشگاه/منزل)، اطلاعات بیمار، نسخه، مدارک و بیمه، و توضیحات همراه بازبینی نهایی دارد. ورود از همان جریان نمایشی موجود استفاده می‌کند و پس از کد 123456 به پذیرش برمی‌گردد. نشست معتبر مستقیماً مرحله انتخاب خدمت را باز می‌کند.

- نشانی فقط برای خدمت منزل الزامی است. اطلاعات بین مراحل حفظ می‌شوند؛ بازخوانی صفحه آن‌ها را بازیابی نمی‌کند.
- ارقام فارسی و عربی تبدیل می‌شوند؛ تاریخ شمسی، کد ملی، همراه، کد نسخه، نوع و اندازه فایل بررسی می‌شوند. اتباع می‌توانند شناسه یا گذرنامه وارد کنند.
- نسخه با کد رهگیری یا فایل JPG/PNG/PDF تا ۱۰ مگابایت ارائه می‌شود؛ مدرک شناسایی اختیاری است. این فایل‌ها فقط انتخاب می‌شوند و آپلود نمی‌شوند.
- بیمه تکمیلی و بیمه پایه «سایر» نام جدا دارند. پوشش، هزینه و زمان باید در مرحله عملیاتی توسط پذیرش تأیید شوند.
- مرحله آخر خلاصه اطلاعات و امکان ویرایش دارد. پایان مسیر فقط تکمیل پیش‌نمایش است؛ ثبت درخواست یا کد پیگیری واقعی ایجاد نمی‌کند و فیلدها را پاک می‌کند.
- HTML پذیرش همچنان خارج از کش PWA است. نسخه کش برای دریافت JS جدید ورود به v7 ارتقا یافته است.

استایل و رفتار مستقل در `assets/css/admission.css` و `assets/js/admission.js` قرار دارند. برای ثبت واقعی، اتصال بک‌اند پذیرش، احراز هویت سمت سرور و ذخیره امن مدارک لازم است.

تست مرورگری اختیاری: با Python Playwright و Chromium نصب‌شده، `python3 scripts/check-admission.py` را اجرا کنید. این تست سرور محلی موقت می‌سازد و ورود، خطاهای فرم، مدارک، ویرایش، پایان مسیر، انقضای نشست و عرض موبایل را بررسی می‌کند.
